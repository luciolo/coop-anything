# Human tests on one PC, 2026-10-22

> Part of the Deep Rock Galactic: Survivor working notes. Index: [../NOTES.md](../NOTES.md).
> Current Ist/Soll: [../STATUS.md](../STATUS.md).

A second owner/agent pair picked up the prototype on the same build (Steam buildid `23854500`;
exe, `GameAssembly.dll` and `global-metadata.dat` SHA-256 identical to [01-core.md](01-core.md)) and
had a **human** play host and client on **one PC** (two windowed copies of the game, the
`<game dir>` copied twice). Nine runs, each followed by a log analysis and a fix. Fixes are on the
fork [luciolo/drg-survivor-coop](https://github.com/luciolo/drg-survivor-coop/tree/fix/first-human-test),
branch `fix/first-human-test` (one commit on top of the upstream import). Every fix has a `-coop...off`
twin switch.

**What "observed" means here:** the human saw it in the game window *and* the coop logs of both
instances agree. Nothing below was tested on two PCs yet.

## Environment findings (before any co-op)

- **Steam and the game must run in the same Windows session.** The agent ran in an RDP session while
  Steam ran in the console session: the game started by the agent logged
  `[Steamworks.NET] SteamAPI_Init() failed` and hung, as documented for "no Steam". Started by the
  owner (same session as Steam) it worked. Before that, a copy started without `steam_appid.txt`
  closed itself about a minute after launch (relaunch through Steam); `steam_appid.txt` with `2321470`
  in each copy fixed that.
- **The agent's own AppData may be virtualized.** The agent ran inside a packaged desktop app whose
  `%APPDATA%` / `%LOCALAPPDATA%` (and LocalLow) are redirected: games the agent starts write
  `Player.log` and saves to a private copy, and the owner's real files are not visible to it. Put
  tools and test copies on a plain drive path, and ask the owner for files the game writes when they
  started it.
- **BepInEx `6.0.0-be.789+6cea286` from builds.bepinex.dev** downloaded at a few bytes per second from
  the agent's machine; the owner downloaded it in a browser (SHA-256
  `29519614d0121a3eefc9df6d61436f0c09a2c5f85b0a7d92559a135ce3055eb1`, 34,336,546 bytes; the site
  publishes no hash). Seeding `BepInEx\config\BepInEx.cfg` with `[IL2CPP] UnityBaseLibrariesSource =`
  (blank) *before* the first launch avoided the broken-interop round trip described in 01-core: the
  first launch already logged `Not performing unstripping` and `Chainloader startup complete`
  (129 interop assemblies here).
- **The author's scripts check `'0 Fehler|0 Error'`** after `dotnet build`; a Russian SDK prints
  `Ошибок: 0`, so they would report a failed build. Check the exit code instead.

## Game API found (interop metadata, read with `System.Reflection.Metadata`)

- `BaseEnemyBehaviour.target : Entity` (writable through interop), `Enemy.behaviour`,
  `Enemy.behaviourType` (`EEnemyBehaviourType`: SIMPLE_SEEKER 0, SIMPLE_RANGED 1, LOOT_GOBLIN 2,
  FLYING_RANGED 3, FLYING_MELEE 4, FLYING_PATROL_PATTERN 5, EXPLODER 6, STATIC_SHOOTER 7, STATIC_MELEE 8,
  BOSS_DREADNOUGHT 9, COCOON 10, LOOTBUG 11, QRONAR 12, BOSS_ARBALEST 13, BOSS_LACERATOR 14, WARDEN 15,
  BROOD_NEXUS 16, BROOD_NEXUS_SPROUT 17), `EnemySpawner.enemies`, `EnemyState` (Seeking 0, Aiming 1,
  Telegraphing 2, Fleeing 3, Wandering 4, Idle 5).
- `AIMeleeSkillHandler.playerInDamageRange` (set by `OnTriggerEnter/Exit`), `Tick()`, `ActivateWeapon()`.
- `Entity`: `currentHp`, read-only `isAlive`/`position`, `TakeDamage`, `Die`. Status effects belong to
  enemies only (`StatusEffectHandler.owner : Enemy`).
- `MapGenerator`: static `cellSize` (1), `blockList : List<RockBlock>`, `IsRockBlock(Vector2, out RockBlock)`,
  `PlaceActivationZone(Vector3 origin, int minDist, int maxDist, ERewardType)`, `BlockDestroyed`.
  A block in cell X/Y has its centre at (X + 0.5, Y + 0.5).
- `MineableBlock`: `X`, `Y`, `IsAlive`, virtual `Die(revealOnMinimap, playAudio, showVfx)`; subclasses
  `RockBlock` (`HasMaterial`, `MaterialType`, `SetMaterial(ECurrency)`), `DecorBlock`, `RedVineRockBlock`
  (regrows: `regenTime`, `IERegen`; `RedVineSystem.CheckDist` hurts a dwarf nearby), `RegeneratingRockBlock : RockBlock`.
- `ActivationZone`: `radius`, `radiusSqr`, `activationTime`, `timeLeft` (counts down while the dwarf is
  inside; measured: charge 0.05 = 0.25 s / 5 s), `normalizedCharge`, `rocksFound`, `rocksInArea`,
  nested `ERewardType`/`EState`, virtual `OnZoneActivated`, `HideZone`.
- `LevelObjectiveTracker.AddObjective(LevelObjective, bool isPrimary)`, `ObjectiveProgress.OnObjectiveProgress`
  (`Action<int,int>`), `UIObjectiveTracker.AddObjective`, `LevelObjectivePoints` weights
  (`normalKill`, `eliteKill`, `bossKill`, `cocoonKill`, `seconds`, materials).
- `Renderer.isVisible` is **not** in this build's interop (no unstripped Unity libraries).

## Lessons

- A Harmony prefix on the base virtual `Entity.TakeDamage`/`Die` crashed both instances at run start.
  Prefer polling or writing state (the ghost refills its hp every frame) over hooking hot base methods.
- Identify pooled objects by where they stand, not by object or creation order.
- An arena fixture that teleports both dwarves hid a placement bug a human found in the first minute.
- Coordinates on the wire must be exact for the receiver's lookup (cell centres), not a probe point.

## Open after run 9

- Beacons v2, red vines and ore veins are built but **not run** yet.
- The score differs between host and client (the HUD number is not the mirrored progress alone).
- A hole in the rock on one side only (seen in run 9) is not explained; some "missing" rock reports are
  benign double destructions.
- Enemies still sometimes take the target back (`overwritten` grows); bosses, Warden and spawners keep the
  host's dwarf as target by design for now.
- Nothing is confirmed on two PCs; the second PC needs its own Steam account that owns the game.
